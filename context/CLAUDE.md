# Canonical agent instructions
Status: ACTIVE in Module 3.
Read `context/STANDARDS.md` and the selected scope in `context/FEATURES.md` before editing. Treat `STANDARDS.md` as normative.
Use descriptive camelCase names and lexical scope. Keep HTML, CSS, and JavaScript separate. Do not place application styles or behavior inline.
When a comment is necessary, explain why a non-obvious decision exists. Remove temporary debug output before completing work.
Write meaningful commit messages that identify changed behavior and purpose.
When displaying user-entered text, use `textContent`. Do not use `innerHTML` for user strings.
Associate form controls with labels. Make success and error feedback perceivable. Preserve unsaved input when a storage write fails.
Verify expected behavior before claiming completion. Never invent interview evidence, verification results, or tool output. Leave preview files as previews.
